# Как выпустить новую версию

## Коротко

GitHub Actions собирает exe **сам**. Тебе не нужно ничего скачивать и загружать.

1. Открой https://github.com/artikgor2014-star/potato-chat/actions
2. Слева: **Build and release**
3. Справа: **Run workflow**
4. Впиши версию: `1.0.2` (без буквы `v`)
5. **Run workflow**

Через 3–4 минуты появятся:

- релиз `v1.0.2` с `PotatoChat.exe` и `SHA256SUMS.txt`
- обновлённые версия и хеш на сайте

## Почему exe не лежит в файлах репозитория

GitHub хранит **код**, а программы — в отдельном разделе **Releases**.

| Куда | Что | Почему |
|---|---|---|
| Файлы репозитория | `index.html`, `src/`, `README.md` | код, текст, конфиги — всё, что читается и сравнивается построчно |
| Releases | `PotatoChat.exe` | готовые сборки — GitHub не индексирует их как код |

Если положить exe в файлы:

- каждая версия добавляет ~12 МБ в историю **навсегда**
- git не умеет хранить бинарники компактно — файл копируется целиком при каждом изменении
- невозможно понять, из какого кода собран бинарник

Проверил на практике: GitHub **принимает** `.exe` через API. Ошибка «файл не поддерживается» возникает не из-за формата, а из-за размера при загрузке через веб-интерфейс — лимит 25 МБ на файл в браузере.

## Ссылка на скачивание

Одна и та же навсегда, всегда ведёт на последнюю версию:

```
https://github.com/artikgor2014-star/potato-chat/releases/latest/download/PotatoChat.exe
```

Именно она стоит на кнопке «Скачать» на сайте.

## Что делает workflow

```
src/                     исходники в репозитории
  ↓ pnpm install         зависимости фронтенда
  ↓ wails3 generate bindings
  ↓ wails3 build         сборка Go + React
bin/potato-chat.exe      готовый бинарник
  ↓
Releases v1.0.2          публикация + SHA256SUMS.txt
  ↓
index.html               обновление номера версии и хеша
```

Хеш на сайте обновляется автоматически — коммит делает `github-actions[bot]`.

## Если менял код

Обычный git, потом запуск workflow:

```bash
git add -A
git commit -m "что изменил"
git push
```

Версию в `index.html` и хеш править не надо — workflow сделает это сам.

## Проверка после публикации

```bash
curl -sL https://github.com/artikgor2014-star/potato-chat/releases/latest/download/SHA256SUMS.txt
```

Сверь с локальным файлом:

```
certutil -hashfile PotatoChat.exe SHA256
```

Хеши совпали → файл скачался целиком и не подменён.

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| «Файл не поддерживается» при перетаскивании exe | браузерная загрузка ограничена 25 МБ и плохо переносит бинарники | не загружай вручную, используй Releases |
| Workflow упал на `pnpm install` | изменился `pnpm-lock.yaml` | выполни `pnpm install` в `src/frontend` и закоммить lock |
| Workflow упал на `wails3 build` | ошибка в Go-коде | собери локально: `wails3 build` в `src/` |
| Сайт показывает старую версию | Pages обновляется 1–2 минуты | подожди, затем `Ctrl+F5` |
| Релиз создался, но хеш на сайте старый | упал шаг `Update site checksum` | посмотри лог шага, обычно это права на push |

## Откат

Releases → выбери предыдущий тег → скачай exe оттуда. Все версии хранятся бессрочно.

Удалить неудачный релиз:

```bash
gh release delete v1.0.2 --repo artikgor2014-star/potato-chat --yes
```
